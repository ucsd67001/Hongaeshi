# 本返し（Hongaeshi）

> 読んだあとに、ありがとうを。

読み終わったあとに、その本を支えた人（著者・出版社・独立系書店）へ気持ちを返す場所。

**いまは架空のポイントで動かすトライアル段階。実際のお金は1円も動かない。**

- 本番: https://hongaeshi.web.app
- Firebase プロジェクト: `hongaeshi`
- ダミーデータのデモ（ログイン不要・単一HTML）: https://hongaeshi.web.app/demo

---

## なぜ作っているか

本を買う以外に、本の世界へお金を返す導線がない。図書館で借りた本、古本で買った本、
昔もらった本 ― 読んで確かに何かをもらったのに、その感謝が著者にも出版社にも書店にも
届かないまま終わる。そこを埋めたい。

ユーザー側の動機は「出版業界を救う」ではなく、もっと個人的なもの。だからキャッチコピーは
**「読んだあとに、ありがとうを。」**で通す。

### トライアルで見たいこと

本物のお金ではないので、**「いくら払うか」は測れない。**測れるのは次の3つ。

1. 配られたポイントを、そもそも使うか
2. どの本に使うか（新刊か、昔読んだ本か、絶版か）
3. **ことばを書くか**（金額だけ送る人と、書く人の比率）

とくに3つめ。購買データでは絶対に取れないのが読後の感情で、
それが出版社・書店にとっての価値になる、というのがこのサービスの賭けどころ。

## 作りの要点（ここだけは先に読んでほしい）

### Cloud Functions を使っていない（＝Blazeプラン不要）

受取人の受取額も本ごとの集計も、**サーバー側で足し込むカウンタを持たない。**
必要なときに `returns` を集計クエリで数える。だから書き込みは
「自分の財布を減らす」＋「返しを1件つくる」の2つだけで済み、無料枠のまま走る。

そのかわり、**この2つが釣り合っていること**を `firestore.rules` の `getAfter()` で縛る。

> ⚠️ アプリ側は財布の更新と返しの作成を**必ず1つの writeBatch で**送ること。
> 別々に送ると必ず弾かれる（`public/共通.js` の `本返しする()`）。

### Firestore の中だけ、名前が ASCII

⚠️ **セキュリティルールの言語は、識別子に日本語を受け付けない**（コレクション名・
フィールド名・関数名。書くと `token recognition error` でデプロイが落ちる。コメントは通る）。
そのため Firestore の中だけ ASCII にして、`public/共通.js` が読み書きの境目で読み替えている。

| 画面での呼び名 | Firestore | 主な項目 |
|---|---|---|
| 財布 | `wallets` | `balance` / `granted` / `created` |
| 返し | `returns` | `book` / `from` / `amount` / `parts` / `toIds` / `text` / `at` |
| 残し | `keeps` | `book` / `from` / `pledge` / `text` / `at` |
| 本 | `books` | `isbn` / `title` / `authorText` / `publisherText` / `year` / `pages` / `cover` / `amazonLinks` / `to[]` |
| 主体 | `entities` | `type` / `name` / `key` / `aliases` / `claimed` / `claimedBy` |
| 申請 | `requests` | `title` / `author` / `publisher` / `isbn` / `memo` / `done` |
| 管理者 | `admins` | uid があれば管理者。**画面からは書けない** |

Firestore から読んだものは `共通.js` の中で必ず日本語のかたちに直してから返す。

### 主体（著者・出版社・書店）は1つのコレクション

`entities` に `type` で混ぜてある。分けなかった理由：

- **返しの宛先が1つのキースペースで済む。**分けると `parts[].to` に型が必要になり、
  結局は合成キーで1つの名前空間に戻すことになる
- **型は後から変わる。**個人経営の古書店は人でもあり店でもある。翻訳者・装丁家を
  足すたびにコレクションを増やしたくない

**IDは型込みの正規化キー**（`author:立花隆` / `publisher:文芸春秋`）。
「あれば取得、無ければ作成」が検索なしで冪等にできる。

### 名寄せの規則は `public/名寄せ.js` にしかない

⚠️ ブラウザ（管理画面からの登録）と手元の道具の**両方から読む。**
同じ規則を2か所に書くと、片方で作ったIDともう片方で作ったIDが食い違って、
**同じ相手が2つの主体に割れる。**

実際に起きたこと：`文藝春秋`（旧字）と `文芸春秋`（新字）が別の主体になった。
NFKC では統合されないので、照合キーだけ新字に寄せている。

**機械で寄せられないもの**（`Ende,Michael` と `ミヒャエル・エンデ` のような
ローマ字と日本語表記）は、管理画面の**統合**機能で人が繋ぐ。
管理画面でいちばん重要なのは編集や削除ではなく、この統合。

### 権限は3段

| | |
|---|---|
| ① 管理者 | `admins` に uid があるひと |
| ② 受取人 | 自分が引き継いだ（`claimedBy` が自分の）主体を持つひと |
| ③ 利用者 | 入っているだけのひと |

②のために新しいコレクションは作らない。`entities` の `claimed` / `claimedBy` で表せる。

⚠️ `admins` は**ルールで書き込み禁止**。増やせるのは Admin SDK からだけ
（画面から増やせると「管理者が自分で管理者を作れる」入口になる）。

### 未ログインでも棚は見える

本と主体は公開読み取り。認証が要るのは**声・本返し・わたしの本返し・受取人の控え**だけ。
リンクを共有されたときに入口しか見えないのは、参加してもらう上で損なので。

### ポイントの配り方

| | |
|---|---|
| はじめて入ったとき | 10,000pt |
| 毎月 | 3,000pt |
| 1回に返せる額 | 100〜50,000pt |
| 受取人に渡る割合 | 90%（決済ぶん5% ＋ 運営5%） |

⚠️ 月のキーは **UTC**（ルールが `request.time` から作るため）。
日本時間では「毎月1日の午前9時に配られる」ことになる。
クライアント側も UTC で揃えてあるので、ずらすなら両方直すこと。

## 書誌データと表紙

外部APIを試した結果。

| | 結果 |
|---|---|
| **openBD**（ISBN引き） | ✓ 57ms・安定。**書誌はこれが正** |
| **国会図書館 SRU**（書名検索） | △ 動くが**1回20秒**、たまにタイムアウト。手元の道具だけで使う |
| 国会図書館 OpenSearch | ✗ 関連度で並ばない。「モモ」で1件目がイラスト辞典だった |
| **Google Books** | △ 鍵が要る。ページ数は取れる。**表紙はほぼ無い**（15冊中1冊） |
| 国会図書館の書影 | ✗ 画像はあるが**並列で叩くと返ってこない**。一次ソースにできない |
| **Amazon** | ✓ 表紙が確実に取れる。**ただし規約上グレー**（下記） |

### 表紙の優先順位

手で入れたもの → **Amazon**（リンクのある本だけ）→ Google（実在確認済み）→ 色の背表紙

⚠️⚠️ **Amazonの画像は規約上グレー。承知のうえで使っている。**
アソシエイト運営規約は商品画像を **PA-API 経由で取得すること**を求めており、
`images/P/{ASIN}` の直リンクは公式に認められた経路ではない。
少しでも趣旨に近づけるため、**Amazonリンクを設定した本にだけ**出している。
PA-API が取れたら（直近180日に3件の適格販売が条件）、そちらへ移すこと。
画像は保存していないので、URLの作り方を変えるだけで済む。

⚠️ **Google Books は、表紙が無くても `imageLinks` を返す。**
返ってくるのは「image not available」の絵で、15冊中8冊がまったく同じ画像だった。
**必ず中身を落として確かめること**（サイズ・重複・縦横比）。

## 動かす

```bash
npm install
firebase serve --project hongaeshi      # ローカル
firebase deploy --project hongaeshi     # デプロイ
```

⚠️ `public/index.html` を**ダブルクリックしても動かない。**
Firebase の設定を `/__/firebase/init.json` から読んでいるため。
設定なしで見たいときは `public/demo.html` を開く。

### 鍵

リポジトリには入れない。`~/.hongaeshi/` に置いて環境変数で渡す。

```bash
export HONGAESHI_KEY="/c/Users/…/.hongaeshi/鍵.json"     # Firebase サービスアカウント
export GOOGLE_BOOKS_KEY=$(cat "…/books api.txt")         # Google Books API
```

## 引っかかりやすいところ

- **`node --check` を通しても足りない。**インラインの `onclick` などは
  **グローバルスコープで動く**ので、`type="module"` の中の変数は見えない。
  値を入れるものは必ず `window` に出した関数を通すこと（ことばを取りこぼした実績あり）
- **`new RegExp(\`…\`)` の中で `[\s\S]` と書かない。**テンプレート文字列が `\s` を `s` に
  潰して `[sS]` になる。`[^]` を使う
- **Node の `fetch`（undici）は国会図書館に 429 で弾かれる。**curl なら通る
- **Firebase Hosting の既定は `max-age=3600`。**SPA なので index.html を1時間掴まれると
  直したものが届かない。いまは全ファイル `no-cache` にしてある

## 決めたこと・保留していること

### 翻訳者は、いまは届け先にしない（2026-09-23 決定）

原著者と出版社だけ。翻訳書では訳者の寄与が大きい（『知的生活』の渡部昇一、
『モモ』の大島かおり、『夜と霧』の池田香代子）が、**将来的に検討**とした。

⚠️ あとから足しても、**それ以前の本返しには反映されない。**
入れるなら早いほうが楽、ということだけ承知のうえでの保留。

### 書店・古書店・図書館は保留（2026-09-23）

⚠️ **これらは本の属性にできない。**『モモ』の著者は誰にとっても同じだが、
「その本を買った書店」「借りた図書館」は読者ごとに違う。
いまのデータの形（本に届け先がぶら下がる）では原理的に表現できない。

入れるなら、**主体への直接の本返し**が必要になる。そのときは
「どの本で出会ったか」を任意で添えられるようにしたい。
書店への支援なのに本のデータが残る、という形にできる。

### 直接の本返し（「応援する」）は未実装

最初の構想にあった3つの行いのうち、**「応援する」（人・出版社・書店への支援）だけ
作っていない。**忘れているのではなく、順番の問題。

⚠️ ただし**直接を主役にすると、ふつうの投げ銭になる。**
「応援する対象＝本、受け取るのは人」という分離がこのサービスの独自性の核で、
読後の感情データもそこから生まれる。**本経由を主、直接を従**に保つこと。

## まだやっていないこと

- 受取人の本人確認とページのClaim（`claimed` / `claimedBy` の口は用意済み）
- 匿名で送っても `from` に uid は残る（信頼できる範囲での試用が前提）
- 実決済（Stripe Connect）と、資金決済法まわりの確認
- 図書館への支援（第二段階）
- 作品IDを ISBN と別に持つこと（いまは版を変えると記録の行き先が消える）
